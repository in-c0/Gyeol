# C5-001 — Event + persistent-memory software surrogate

Status: **PRE-REGISTERED / MACHINE-SIDE SURROGATE**  
Parent: #11 M1-C5  
Depends on: B-001 frozen dataset manifest

## Purpose

Test whether a persistent temporal-memory channel adds enough **task utility or digital temporal-state reduction** to justify keeping the C5 analog event+memory device branch active.

This experiment does **not** test:

- physical sensor fidelity
- analog circuit energy
- photophysics
- fabrication feasibility
- whole-device power

A positive result only advances C5 from literature rationale to a Gyeol-specific representation hypothesis.

## Representation

For each feature/channel and 50 ms timestep:

```text
fast[t]   = event[t]
alpha     = exp(-dt / tau)
memory[t] = alpha * memory[t-1] + event[t]
```

The recurrence is a deliberately simple linear reservoir surrogate. It is not claimed to reproduce the exact transfer function of any published device.

Implementation: `tools/c5_event_memory_surrogate.py`.

### Feature-scale control

The unnormalised recurrence has tau-dependent steady-state gain. To prevent a classifier from appearing to benefit merely from a larger numerical amplitude:

- fit feature mean/scale using **tuning videos only** for each representation/tau;
- apply those frozen statistics to held-out data;
- never recompute normalisation on held-out data;
- report the raw and normalised feature distributions in the result artifact.

This does not make the surrogate more physically faithful; it isolates temporal persistence from arbitrary feature scale.

## Input contract

Use the same frozen B-001 tuning/held-out manifest and event representation as the event-first gate experiment.

No C5 parameter selection begins before `experiments/results/B-001-manifest.json` is committed.

## Representations

### C5-E0 — instantaneous event-only

Use the B-001 instantaneous event features at the current timestep without a persistent temporal-memory channel.

### C5-EM — event + memory

Concatenate the same current-timestep event features with the persistent-memory channel generated by the recurrence above.

### C5-EW — event-only with explicit digital history

For the state-replacement test only, provide an explicit downstream window of event-only feature vectors. This is the digital temporal state that C5-EM is hypothesised to replace.

## Downstream decision model

Use the same downstream model/classifier family across representations.

- For **Path A**, C5-E0 and C5-EM both receive exactly one current timestep and must use the same trainable-parameter budget within ±5%. If input dimensionality would otherwise change trainable parameter count, use a pre-declared fixed projection/width adjustment fitted only on tuning data.
- For **Path B**, the model family and trainable-parameter budget remain matched within ±5%, but the explicit temporal window is allowed to differ because temporal-state reduction is the quantity under test.

All model-family, projection and parameter-budget details must be committed before held-out evaluation.

## Tau sweep

Candidate memory constants:

```text
50 ms
100 ms
250 ms
500 ms
1000 ms
```

Select `tau` using **tuning videos only**. Freeze the selected value before held-out evaluation.

A sensitivity result must report every tau candidate, not only the winner.

## Digital-window sweep for Path B

Candidate C5-EW and C5-EM downstream history windows:

```text
1, 2, 4, 8, 16, 20 timesteps
```

At 50 ms/timestep these correspond to 50 ms through 1 second of explicit downstream history.

For each representation on tuning data:

1. evaluate every candidate window under the same false-wake/duty constraints;
2. identify the maximum tuning recall;
3. select the **smallest** window whose recall is within 1.0 percentage point of that representation's maximum tuning recall;
4. freeze that window before held-out evaluation.

This rule prevents choosing an unnecessarily large event-only window solely to manufacture an apparent C5 state reduction.

## Primary task

Use the same task-relevant action/event-onset target defined by B-001 so C5 is evaluated on a Gyeol-relevant temporal-context problem rather than a convenient unrelated benchmark.

If B-001 is later superseded by a better pre-registered embodied-perception task, C5 must document the rebase before looking at C5 held-out results.

## Metrics

Report:

- important-event recall
- false wakes/hour
- median wake latency
- awake duty cycle
- downstream trainable parameter count
- explicit downstream temporal window length
- downstream temporal input/state values
- persistent sensor-surrogate state values, reported separately
- estimated digital temporal recurrence multiplies/adds from explicit operation accounting
- representation bytes moved from the sensing representation to the downstream decision stage

Operation counts are **accounting**, not an energy estimate.

## Keep-active threshold

C5 remains an active moonshot only if the held-out result satisfies **at least one** path below while respecting the same false-wake and duty-cycle bounds used by B-001.

### Path A — task-quality gain at matched context

Compare **C5-EM vs C5-E0** using one current timestep for both and matched model/parameter budgets.

Pass Path A only if C5-EM:

- improves important-event recall by **>=2.0 percentage points**;
- does not increase median wake latency by >50 ms;
- does not violate B-001 false-wake/duty-cycle bounds.

### Path B — replace downstream digital temporal state

Compare **C5-EM vs C5-EW** after each representation's window is selected using the tuning-only minimum-near-best rule above.

Pass Path B only if held-out C5-EM:

- is within **1.0 percentage point** of C5-EW important-event recall;
- respects the same false-wake/duty-cycle bounds;
- uses a frozen explicit downstream window `W_EM <= W_EW / 2`;
- reduces explicitly counted **downstream digital temporal input/state or temporal accumulation operations by >=2x**;
- moves no more representation bytes to the downstream stage than C5-EW over the matched decision horizon.

The C5-EM persistent-memory state is reported separately rather than silently omitted. Path B tests whether that state could move into the sensing plane and thereby replace downstream digital history.

Merely appending memory features while retaining the same downstream history does not pass Path B.

## Robustness requirement

A passing result must not depend on a single sharp tau optimum.

At least one immediately adjacent tested tau to the selected value must remain within:

- 1.0 percentage point of selected-tau recall, and
- the same false-wake/duty-cycle constraints.

For an endpoint tau (50 ms or 1000 ms), its one available adjacent candidate is sufficient.

## Failure / park rule

PARK C5 if neither Path A nor Path B passes on held-out data.

A visually interesting memory trace, a literature result, or lower operation count in isolation is not sufficient to keep the branch active.

If C5 is parked, it may be reopened only by new evidence that materially changes the task, representation, or physical-device opportunity; the reopening rationale must be recorded before new held-out testing.

## Advance beyond software only if

If C5 passes the surrogate:

1. identify the exact downstream digital state/operations the physical C5 architecture could replace;
2. construct a circuit/subsystem energy model with uncertainty bounds;
3. require a credible **>=10x** energy advantage in that constrained temporal-context subsystem before custom-device work;
4. show from C1/C2 measurements that this subsystem is a material Gyeol bottleneck;
5. identify a fabrication/integration path.

Only measured hardware can validate a hardware-energy claim.
